## ③ 发现清单

### F1 🟠P1 — 后端默认门禁红：真实面板 PSI 基线测试失败
- **类别**：Functional / Test-gate
- **位置**：`backend/tests/test_monitor_trigger_caliber.py:347-348`
- **描述**：`assert base["max"] <= M.PSI_DEGRADED, "基线不应已降级"` 失败。
- **证据**（实测输出）：
  ```
  tests\test_monitor_trigger_caliber.py:348: in test_real_panel_injection_sensitivity_table
      assert base["max"] <= M.PSI_DEGRADED, "基线不应已降级"
  E   AssertionError: 基线不应已降级
  E   assert 0.5149 <= 0.25
  E    +  where 0.25 = M.PSI_DEGRADED
  ```
  测试 docstring 记录写入时基线为 **0.2024**，当前实测 **0.5149**（≈2.5×）。该用例 `skipif(not REAL_FEATURES.exists())` —— CI 无本地面板会 skip，但**本机/带数据环境必红**。
- **性质**：数据依赖用例。要么本机真实特征面板确已漂移（PSI 0.51 本身就是监控该报警的信号），要么用例基线假设过期。
- **建议**：先查 `REAL_FEATURES` 面板的 `data_date`/生成时间判断是否真漂移；若确为漂移→按数据面处理（非门禁问题），若为环境陈旧→给用例加 `@pytest.mark.network`/数据版本 gate，勿裸跑在默认门禁。

### F2 🟠P1 — 前端测试门禁非确定：默认并行**静默丢 1 个测试文件**
- **类别**：Console/Errors（门禁可信度）
- **位置**：`frontend/vitest.config.ts`（`include: src/**/*.test.{ts,tsx}`，未固定 pool）
- **描述**：磁盘上共 **16** 个 `*.test.ts(x)`，但 `npx vitest run` 每次只执行 **15** 个，**且每次丢的不同**：run1 丢 `EtfDetail/IndustryPie.test.tsx`（→131 tests），run2 丢 `DataCenter/syncAlertWiring.test.tsx`（→137 tests）。加 `--no-file-parallelism` 才 16/143 全跑。运行期伴随 1 个未处理错误 `EPERM: operation not permitted, open '...\Temp\...\web\<hash>'`（worker 写临时文件被拒）。
- **证据**：131 = 143 − 12（IndustryPie 12 例）；137 = 143 − 6（syncAlertWiring 6 例）；三者互洽。
- **影响**：CI/本地"绿"可能在**漏跑用例**的情况下变绿 —— 门禁不可信（与项目"守门测试"立意直接冲突）。
- **建议**：`vitest.config.ts` 固定 `pool`/`poolOptions`（如 `singleThread` 或 `forks`），或排查 worker 临时目录写权限；并加**用例/文件计数断言**（期望 16 文件）防止再次静默丢。

### F3 🟡P2 — ETF 详情 K 线：null OHLC 被 `?? 0` 兜成 0（渲染成"价格 0"的假蜡烛）
- **类别**：Content / Functional（0 冒充不可得）
- **位置**：`frontend/src/pages/EtfDetail/index.tsx:814-825`
- **描述**：
  ```ts
  return kline.bars.map((b) => ({
    date: b.date,
    open: b.open ?? 0, close: b.close ?? 0,
    high: b.high ?? 0, low: b.low ?? 0, volume: b.volume ?? 0,
    amount: null,
  }));
  ```
  类型 `EtfKlineBar`（`types/etf.ts:189-196`）明确声明 OHLC 为 `number | null`；后端 `app/data/etf.py:547-548` 用 `_num(r[1..4])`，对 `'-'`（停牌/无数据）返回 `None` ⇒ **后端确实可能回 null**。前端兜成 0 会让该根 K 线画在价格 0 处（图上一条坠到 0 的假影线）。
- **佐证**：同文件对 `?? 0` 是红线（见 `:449`、`:504`、`:660` 的显式禁止注释），此处属**自相矛盾的漏网点**。
- **建议**：null OHLC 的 bar 跳过或按"缺口"处理，不得填 0。

### F4 🟡P3 — `MarketHeat` 类型是死代码且契约失真
- **位置**：`frontend/src/types/stock.ts:318-325`
- **描述**：`MarketHeat` 声明 `up/down/flat/limit_up/limit_down/total_amount_yi: number`（非空），但全仓**无任何引用**（真实消费类型是 `HeatBlock`，其字段为可选/可空）。该类型会误导后续开发者按非空取值。
- **建议**：删除 `MarketHeat`，或与 `HeatBlock` 对齐。

### F5 🟡P3 — StockDetail `(mainNet ?? 0) >= 0` 方向兜底（当前不可达，但脆弱）
- **位置**：`frontend/src/pages/StockDetail/index.tsx:542`
- **描述**：`const inflow = (mainNet ?? 0) >= 0;` —— 正是项目红线禁止的 `(x ?? 0) >= 0` 造方向写法。当前仅在该 RatioBar 于 `mainOk`（`main_net_yi != null`）分支下渲染，故**暂不触发**；但一旦分支重构即会"取数失败染成红涨"。
- **建议**：改为 `const inflow = mainNet != null && mainNet >= 0;`。

### F6 🟡P3 — 市场概览 daily+rt 合并用 `as unknown as` 绕过类型检查
- **位置**：`frontend/src/pages/MarketOverview/index.tsx:86-91`
- **描述**：`{ ...(daily.data as object), ...(rtData as object) } as unknown as MarketOverviewData` —— 双重断言使 TS **不校验**合并结果；若 daily/rt 存在**同名不同型**字段（如 `heat` 形状漂移），编译期无法发现。
- **建议**：写显式 typed merge（逐块 `??` 取并断言各块类型），去掉 `unknown as`。

### F7 🟡P3 — DataCenter 同步进度 `?? 0` 与同文件 null 纪律不一致
- **位置**：`frontend/src/pages/DataCenter/index.tsx:967 / 971 / 975`（`sync?.percent ?? 0`、`completed_count ?? 0`）
- **描述**：同文件 `:993/:1006` 明确禁止 `?? 0` 兜未知；进度条处却用 `?? 0`，未知时显示 "0%"。低危（busy 分支下 percent 一般存在），但口径应统一。

### F8 🟡P3 — BreadthPanel `Donut` 仍用 `heat.up ?? 0`
- **位置**：`frontend/src/pages/MarketOverview/BreadthPanel.tsx:72`
- **描述**：组件 `:101-107` 已明确"up/down/flat 不得 `?? 0`"，但同文件的 `Donut` 子组件仍 `heat.up ?? 0`。受 `status==='ok'` 门控，可达性低；属遗留不一致。

### F9 🟢P3（提示）— AI 精选标签在前端按阈值分档
- **位置**：`frontend/src/pages/MarketOverview/AiPicksPanel.tsx:50-56`
- **描述**：`tagOf(score)` 用前端硬编码阈值把后端 `pred_score` 映射为「强烈看多/看多/震荡/看空/强烈看空」。分值真实、仅标签客户端生成。若后端亦下发 label，则存在**双源分歧**风险。建议确认单一事实来源。

## ④ 数据一致性抽样结论（正面）

- **响应信封/错误处理**：`api/client.ts` 严格解包 `{code,message,data}`，`code!==0` 抛 `ApiError`；未登记错误码显式标注；内部异常类名被 `sanitizeApiMessage` 屏蔽 —— 无"美化降级"。
- **方向/单位口径**：`KpiCards.tsx`、`OverviewCards.tsx`、`BreadthPanel.tsx`、`Watchlist`、`Etf` 等处均以"可空字段渲染 —、不染色"为纪律，并有大量守门测试固化（如 `IndustryConcentration.test.tsx`、`syncAlertWiring.test.tsx`）。
- **ETF overview 日期口径（历史 F2）**：后端 `_etf_data_date()` 已改用**交易日**（`etf.py:488` 注释"审计 F2：用交易日，与快照内 date 口径一致"）—— 该历史问题本轮**确认已修复**。
- **降级态**：`/health`、`/health/ready` 如实报 `redis=degraded/disabled`；readiness 仅以 sqlite+data_root 为准（Redis 不阻断接流量）；缓存层 Redis 不可用回退进程内 LRU（`cache/memory.py`）。✅
