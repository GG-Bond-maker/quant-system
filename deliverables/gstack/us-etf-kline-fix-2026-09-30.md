## 📌 TL;DR

- **结论：不需要接入任何新数据源。** 现有腾讯源**完全支持**美股日线，

  比 A 股能力更强。
- **工作量**：约 30 行（含缓存键调整），**无新依赖、无新数据源、无 schema 改动。**
- **替代源已实测全灭**：Yahoo 403、Stooq 返回占位页、东财美股接口断连
  ⇒ **腾讯是唯一可用来源**，这反而强化了"必须修后缀"的紧迫性。
- **上限已精确定界**：美股 **2000 根**（2018-10-12 起）；⚠️ `limit=2001` → **整个响应变空**，必须硬夹紧。

## 1. 根因诊断

### 1.1 问题代码

`backend/app/data/etf.py:406-410`：

```python
def _build() -> list[dict]:
    if market == "us":
        param = f"us{symbol}.OQ,day,,,{limit},qfq"   # ← 后缀写死 .OQ（Nasdaq）
    else:
        param = f"{market}{symbol},day,,,{limit},qfq"
```

**`.OQ` 是 Nasdaq 的交易所后缀。** 但绝大多数美股 ETF（SPY/IWM/DIA/GLD/XLF…）
在 **NYSE Arca（`.AM`）** 上市，不在 Nasdaq。

### 1.2 决定性的对照实验

同一只标的 `SPY`、同一接口、只改后缀：

| 请求 | 返回根数 |
|---|---|
| `usSPY.OQ`（**代码当前用的**） | **1** |
| `usSPY.N` | 1 |
| `usSPY.AM` | **20** ✅ |

> 返回 1 根不是"没数据"，而是腾讯对**错误后缀**只回当前快照——这个"1 根"
> 极具迷惑性：**接口 HTTP 200、字段结构完整、也能解析出一个数**，
> 所以既不会报错、也不会被测试发现，只会在图上表现为"一条孤点/空图"。

### 1.3 全量摸底（16 只 US_CATALOG）

## 2. 推荐方案：`qt` 字段自动发现后缀

### 2.1 关键机制

腾讯响应结构（`usSPY.OQ` 请求）：

```
data.usSPY.OQ = {
  'day'    : [...]            ← 日线（错误后缀时只有 1 根）
  'qt'     : {'usSPY.OQ': ['delay', '标普500指数ETF-SPDR', 'SPY.AM', ...]}
                                                              ↑ 第 [2] 位 = 真实标识
  'pandata': {...}
}
```

**即使后缀写错，`qt[2]` 仍回传真实标识**（`SPY.AM`）⇒ 可以用它纠正后再取一次。

### 2.2 实测验证

| 代码 | `qt` 回传 | 用真实标识重取 |
|---|---|---|
| SPY | `SPY.AM` | **60 根**，2026-07-07 ~ 2026-09-29 ✅ |
| QQQ | `QQQ.OQ` | **60 根** ✅ |
| IBIT | `IBIT.OQ` | **60 根** ✅ |
| TLT | `TLT.OQ` | **60 根** ✅ |
| GLD | `GLD.AM` | **60 根** ✅ |

⇒ **5/5 全部成功**。

### 2.3 长周期上限（额外红利，实测已精确定界）

美股日线上限 **2000 根**，且边界是**断崖式**的：

| `limit` | SPY.AM 实际返回 | 起始日期 |
|---|---|---|
| 200 | 200 | 2025-12-11 |
| 400 | 400 | 2025-02-26 |
| 800 | 800 | 2023-07-24 |
| 1000 | 1000 | 2022-10-04 |
| 1200 | 1200 | 2021-12-16 |
| **2000** | **2000** ✅ | **2018-10-12** |
| **2001** | **0（整个响应变空）** ⚠️ | — |
| 5000 | 0 | — |

> ⚠️ **`limit=2001` 不是"少给几根"，而是整条 `data` 变空**——
> 这与 A 股"超限只给 640 根"的表现完全不同，是个**必须写进代码上限保护**的坑。
> 建议 `min(limit, 2000)` 硬夹紧。

**A 股对照（复核 2026-09-30）**：

| `limit` | sh510300 实际返回 | 备注 |
|---|---|---|
| 800 | **801** | 可用最大值 |
| 1000 | **641**（更少！） | 超限后**反向缩水** |

⇒ 中美两个市场的"超限行为"**完全不同**（A 股缩水、美股清空），
`_KLINE_LIMIT = 800`（`etf.py:671`）这个**全局值**对美股是**约束而非保护**：
若要让美股支持更长周期，需按 market 分别取值（美股 2000 / A 股 800）。
**这属于增强项，建议与主修复分开提交。**

## 3. 实现方案

### 3.1 改造 `fetch_kline`（`app/data/etf.py:393`）

```python
_US_SUFFIXES = ("AM", "OQ", "N")          # NYSE Arca / Nasdaq / NYSE
_US_SUFFIX_TTL = 24 * 3600                # 后缀映射缓存 24h（交易所归属极少变）

def _us_real_symbol(symbol: str) -> str:
    """把裸代码（如 SPY）解析成腾讯真实标识（如 SPY.AM）。

    腾讯对**错误后缀**只返回 1 根快照，但 ``qt`` 字段仍回传真实标识，
    故用它自动发现——避免维护一张会过期的交易所映射表。
    解析失败则退回 ``.OQ``（保持既有行为，不引入新失败模式）。
    """
    key = f"us_sym:{symbol}"
    cached = _cache_get(key)
    if cached:
        return cached
    for suf in _US_SUFFIXES:
        cand = f"{symbol}.{suf}"
        try:
            node = _probe_us_node(cand)      # 拉 limit=2 即可
        except Exception:
            continue
        # 优先信 qt 回传的真实标识
        for v in (node.get("qt") or {}).values():
            if isinstance(v, list) and len(v) > 2 and isinstance(v[2], str) and "." in v[2]:
                real = v[2]
                _cache_put(key, real, _US_SUFFIX_TTL)
                return real
        # qt 没有但已能取到足够日线 ⇒ 该后缀本身就是对的
        days = node.get("day") or node.get("qfqday") or []
        if len(days) > 1:
            _cache_put(key, cand, _US_SUFFIX_TTL)
            return cand
    return f"{symbol}.OQ"                    # 兜底：与改造前一致
```

主函数里的关键改动：

```python
def fetch_kline(market: str, symbol: str, limit: int = 320, force: bool = False):
    # ⚠️ 缓存键必须含"解析后的真实标识"：否则先请求 `.OQ`（1 根）会被缓存，
    #    后续即使解析对了也命中脏缓存（改造中最容易踩的坑）。
    if market == "us":
        real = _us_real_symbol(symbol)        # SPY -> SPY.AM
        key = f"kline:us:{real}:{limit}"
    else:
        real = symbol
        key = f"kline:{market}:{symbol}:{limit}"

    def _build() -> list[dict]:
        if market == "us":
            param = f"us{real},day,,,{limit},qfq"       # ← 用真实标识
            node_key = f"us{real}"
        else:
            param = f"{market}{symbol},day,,,{limit},qfq"
            node_key = f"{market}{symbol}"
        ...
        node = ((data or {}).get("data") or {}).get(node_key) or {}
```

### 3.2 必须同时处理的点

| # | 事项 | 原因 |
|---|---|---|
| 1 | **缓存键改用真实标识** | 否则 `.OQ` 那次「1 根」会被缓存污染后续请求 |
| 2 | **`qt` 解析要有防御** | `qt` 是 `{key: [list]}`，需校验 `len(v)>2` 且 `v[2]` 是含 `.` 的字符串 |
| 3 | **`_us_real_symbol` 自身要缓存** | 否则每次请求多 1~3 次探测 HTTP |
| 4 | **失败兜底回 `.OQ`** | 保证"最坏情况不退步" |
| 5 | **`limit` 硬夹紧 2000** | ⚠️ `limit=2001` 会让**整个响应变空**（见 §2.3），必须 `min(limit, 2000)` |
| 6 | **加数据质量断言（防静默退化）** | 见下 |

### 3.2.1 数据质量断言（本次事故的根源是"静默"，所以要防复发）

只改后缀**不解决"为什么没人发现"**。建议在 `fetch_kline` 里加一条轻量自检：

```python
# 美股日线：请求 limit>1 却只回 1 根 ⇒ 极可能是后缀错误（而非"该股只有1天数据"）
if market == "us" and limit > 1 and len(out) == 1:
    log.warning("kline:us:%s limit=%s 仅返回 1 根 —— 疑似交易所后缀错误", symbol, limit)
    # 触发一次后缀重解析（清缓存后重试），仍失败则返回原结果
```

**理由**：正常标的请求 320 根只回 1 根，是**物理上不可能**的（除非当日新上市）。
把它变成一个**可观测信号**，下次同类问题会自己冒出来。

### 3.3 静态映射兜底（推荐：静态表优先 + `qt` 探测次之）

若不想每次都走探测 HTTP，可直接写表（16 只很少改）：

```python
_US_SYMBOL_MAP = {
    # Nasdaq（.OQ）
    "QQQ": "QQQ.OQ", "TLT": "TLT.OQ", "IBIT": "IBIT.OQ",
    # NYSE Arca（.AM）—— 其余 13 只
    "SPY": "SPY.AM", "IWM": "IWM.AM", "DIA": "DIA.AM", "VTI": "VTI.AM",
    "EEM": "EEM.AM", "GLD": "GLD.AM", "XLF": "XLF.AM", "XLK": "XLK.AM",
    "XLV": "XLV.AM", "XLE": "XLE.AM", "ARKK": "ARKK.AM", "SOXL": "SOXL.AM",
    "HYG": "HYG.AM",
}
```

**推荐做法：两者结合** —— 静态表**优先**（零额外请求、可静态断言），
表里没有的才走 `qt` 探测（覆盖新增标的，无需改代码）。
16/16 命中静态表，探测只在未来新增标的时发生一次。

> ✅ 全量摸底已确认 **16/16 均可解析**（2026-09-30 实测，无一失败）：
> 13 只 `.AM` + 3 只 `.OQ`，与 §1.3 表格完全一致。

## 4. 备选数据源实测（2026-09-30 逐个验证，均**不可用**）

在决定"修后缀"之前，我把常见替代源都试了一遍，结论是**都不通或不可靠**：

| 来源 | 实测结果 | 判定 |
|---|---|---|
| **腾讯（现状）** | ✅ 日线 2000 根、0.1s 延迟、无需代理 | **唯一可用主力** |
| yfinance / Yahoo | ❌ **HTTP 403**（走代理、直连都 403；返回的是 Yahoo 中文拦截页） | 不可用 |
| Stooq | ❌ 所有端点（日线 CSV / 首页 / 报价页 / .pl 域名）**返回同一个 796 字节 HTML 占位页** | 不可用（疑似被拦） |
| 东方财富 `push2his`（美股） | ❌ `RemoteProtocolError: Server disconnected`（`push2` 报价接口连 A 股也不通了） | 不可用 |
| Alpha Vantage / Polygon / Tiingo | 需 API key，免费额度极小 / 付费 | 未接入 |

> **关键结论：本机网络环境下，腾讯是唯一稳定的美股日线来源。**
> 这反而**强化了"修后缀"的紧迫性**——没有备用方案可退。
> （注：Yahoo 403 与 Stooq 占位页**不能**据此断定"这些源本身不可用"，
> 也可能是本机网络/代理所致；但**对当前部署环境而言，它们确实取不到数**。）

### 4.1 一个重要发现：**数据源一直都在，只是没人调用**

排查过程中确认：`fetch_kline` 把 `.OQ` 写死之后，
**腾讯对该错误后缀依然返回 HTTP 200 + 完整 JSON 结构**（只是 `day` 数组只有 1 条）。
这意味着：

- 它**不会抛异常** ⇒ 不会被 `try/except` 捕获 ⇒ 不会进降级日志；
- 它**字段结构完整** ⇒ 能被正常解析成一个点 ⇒ 前端画出一个孤点；
- 它**HTTP 200** ⇒ 统一响应契约下 `code=0` ⇒ 监控无告警。

**三重"看起来很健康"叠加**，导致一个字母的错误潜伏到了现在。
——这也再次印证本项目那条已知的架构性风险：**HTTP 恒 200 + 零 5xx ≠ 健康**，
基于状态码的表层监控对此类缺陷**系统性失效**。

**建议**：修复时同步加一条**数据质量断言**（见 §5.1），而不是只改后缀——
否则下次再有类似"静默退化"，依然要靠人肉发现。
