# Task 7 A/B 对比：ma_cross 迁入 broker 闸门

- 场景：三只不同板块标的（000001.SZ 主板 / 300750.SZ 创业板 / 000017.SZ 主板），
  窗口 2025-08-08~2026-08-28，参数 5/20/3%，基准沪深300（真实数据）。
- legacy = 旧 ma_cross 专用引擎（无停牌/涨跌停/T+1 闸门，不计冲击成本）；
  framework = 策略框架 + broker（全套闸门 + 涨跌停列 + 线性冲击）。

## 结果（task7-engine-compare.json）

| 指标 | legacy（无闸门） | framework（闸门） | diff |
|---|---|---|---|
| 年化 | **+8.89%** | -18.72% | -27.6pp |
| 夏普 | 0.410 | -0.560 | -0.97 |
| 最大回撤 | 48.8% | 43.95% | -4.85pp |
| 成交笔数 | 97 | 149 | +52 |
| 期末净值 | 1.0904 | 0.8102 | -0.28 |

## 差异来源解释

1. **旧引擎的"收益"含大量不可执行成交**：涨停价买入（如一字板）、无 T+1
   约束、无停牌闸门——这些正是审核 P1-8 判定"结果偏乐观"的机制。
   27.6pp 的差值是两引擎口径差异的总量，其中闸门拦截与执行时点偏移为主。
2. **调仓语义差异是第二来源**：框架版每日把持仓对齐目标（目标漂移即
   再平衡，149 笔 vs 97 笔），旧引擎只在目标集合变化时交易且预算分配
   规则不同。这不是"框架版更差"，而是两个引擎本就不可比——统一的
   全部意义在于此后页面上的 ma_cross 与 donchian/rsi 数字同口径。
3. 回撤反而更小（-4.85pp）：闸门拦截了部分高位的不可执行买入。
4. **结论方向：收益虚高的修正，量级远超预期**（审核报告原估"依赖涨停
   命中频率"【存疑】，实测这三个动量标的上虚高 27.6pp/年）。

## 顺带修复

- `run_strategy` 此前构造的 uni_d **从不携带 limit 列**——框架策略
  （donchian/rsi）的涨跌停闸门同样一直失效（broker 退化为 ±20% 默认）。
  现已透传 limit 列；`_load_strategy_bars` 按板块生成 qfq 域涨跌停
  （主板 10%/创业科创 20%/北交所 30%）。
- 已知边界：ST 历史口径（5%）缺失沿用当前快照、新股不设限期未特判
  （闸门偏松/偏严方向已注明，见 task6-AB.md 的同源限制）。

## 回滚

`use_legacy_engine=true` 请求参数可一键回退旧引擎（响应 strategy_engine
字段标注 legacy_no_gates），无需改代码。
