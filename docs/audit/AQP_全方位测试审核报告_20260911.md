## 3. 问题清单

### 🟠 P1（严重）

#### P1-1　首页聚合请求绕过聚合超时约定，仍用 15s 默认超时

- **现象**：`MarketOverview`（首页 `/`）通过 `useApi()`（SWR）直连 `/api/v1/market/overview/rt` 与 `/api/v1/market/overview/daily`。SWR 的 `fetcher` 只调用 `get(url, params)`，**未透传 timeout** → 落回 `client.ts` 默认 **15000ms**；而 `marketApi.overviewRt/overviewDaily` 中定义的 `OVERVIEW_TIMEOUT = 60_000` 未在首屏路径生效（`marketApi.overviewRt(true)` 仅手动轻刷新用到）。
- **复现命令**：
  ```bash
  cd backend && .venv/Scripts/python.exe ../.workbuddy/smoke_probe_20260911.py
  # 观察 /api/v1/market/overview/rt 与 /overview 的 sec 字段
  ```
- **证据（原始输出片段）**：
  ```
  {"path": "/api/v1/market/overview/rt", "http": 200, "sec": 22.91, ...}
  {"path": "/api/v1/market/overview",    "http": 200, "sec": 25.31, ...}
  ```
  前端约定（`client.ts:112`）："聚合接口（如 /panels 需并发访问多个外部数据源）需放宽"；`market.ts:8` 已定义 `OVERVIEW_TIMEOUT = 60_000`。
- **定位**：`frontend/src/api/swr.ts:19-20`（fetcher）、`frontend/src/api/swr.ts:39-44`（useApi 无 timeout 入口）、`frontend/src/pages/MarketOverview/index.tsx:38-45`。
- **影响**：后端重启 / 缓存过期(TTL 300s) / 预热失败时，首页 rt/daily 请求在 15s 处抛出 `ApiError('请求超时')`；叠加 P2-1（首页无错误提示）→ 用户看到无数据/骨架的空首页，无任何说明。生产端 `_overview_warmer`（240s 续期）可缓解常态，但冷启动窗口仍会命中。
- **建议修复方向**：给 `useApi` 增加 timeout 透传（如 `config.timeout` → `fetcher(url, params, timeout)`），或首屏改走 `marketApi.*` 的 60s 通道。**建议交 Engineer 处理。**

### 🟡 P2（一般）

#### P2-1　缺少应用级 ErrorBoundary；首页无错误态
- **现象**：全仓 `grep -rn "ErrorBoundary|componentDidCatch"` 结果为空；`MarketOverview/index.tsx` 对两个 `useApi` 的 `error` 无任何消费，`loading` 计算也不含 error。
- **定位**：`frontend/src/main.tsx:8-12`、`frontend/src/App.tsx:75-115`、`frontend/src/pages/MarketOverview/index.tsx:47,104-116`。
- **影响**：任一页面渲染期抛错 → 整棵 React 树卸载 → **全站白屏**（现有 `Suspense` 仅兜 loading，不兜 error）；首页数据失败仅有空态、无"重试/不可用"提示（项目已具备 `ErrorState` 组件却未在此使用）。
- **建议**：`App` 外层包 ErrorBoundary（带重试/刷新）；首页补 `ErrorState`。

#### P2-2　`GET /api/v1/settings` 未鉴权，与前端守卫及注释不一致
- **现象**：前端 `/settings` 路由包 `<RequireAuth>`，`App.tsx:103` 注释称"系统设置的后端接口全部 require_role 保护"；但后端 `GET /api/v1/settings` 无 `Depends`，无 token 返回 `code=0`。
- **证据**：`{"path": "/api/v1/settings", ... "no_token_code": 0, ...}`
- **定位**：`backend/app/api/v1/app_settings.py:140`。
- **影响**：匿名可读全部系统配置（存储量 / 上次同步 / 缓存与磁盘健康）。防御纵深缺口。
- **建议**：对齐语义——给 GET 加 `require_role("viewer")`，或修正注释。

#### P2-3　只读端点普遍匿名可读（前端守卫与后端 RBAC 不一致）
- **现象**：以下 GET 无 token 均 `code=0`，但其前端路由分别包了 `RequireRole(researcher)` / `RequireAuth`：
  - `/desk/kill-switch`、`/desk/exclusion`、`/desk/exclusion/screen`、`/desk/orders`、`/desk/account`、`/desk/capacity`
  - `/studio/factors`、`/ops/lineage`、`/ops/dag`
- **证据（探针 no_token_code=0）**：上述 9 条。
- **定位**：`backend/app/api/v1/desk.py:51,86,152,203,235,248`（GET 无 `require_role`）；`studio.py:294`；`ops.py:267,359`。
- **影响**：paper trading 账户/委托、任务血缘/DAG 等状态匿名可读。`test_rbac.py` 注释表明"viewer 可访问公开 GET 接口"，若"公开读"为既定设计则应统一文档；否则应补齐读鉴权。
- **建议**：确认设计意图；对 `/desk`、`/ops`、`/studio` 读端点补 `require_role("viewer"/"researcher")`。

#### P2-4　`405 Method Not Allowed` 被归类为 `50000` 系统异常
- **现象**：对 PUT-only 路由发 POST → HTTP 200 + `code=50000`（"系统异常"），前端会误判为后端故障。
- **复现**：
  ```bash
  cd backend && .venv/Scripts/python.exe ../.workbuddy/smoke_probe2_20260911.py
  # POST /api/v1/settings/preferences （实际为 PUT）→ code=50000；正确 PUT → 40100
  ```
- **定位**：`backend/app/core/errors.py:99-102`，`_http` 处理器把非 401/403/404 的状态码一律映射为 `ERR_SYSTEM`。
- **建议**：为 405（及其他 4xx）增加独立业务码（如 `40500 ERR_METHOD`）或按段细分。
