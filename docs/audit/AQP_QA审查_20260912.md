## 6. 结论与遗留风险

### 6.1 结论

1. **`93fa52d` 未经全量回归即入库，本次审查补上了这个验证，结果是不通过（8 红）**。其中 **1 条是源码回归（QA-01，P0）**：`score_topk` 预警在股票池快照缺失时静默失效；**7 条是测试侧欠账（QA-02/03/04，P1）**：安全加固收紧了端点鉴权，但 `test_api.py`、`test_desk_attribution_benchmark.py`、`test_portfolio.py` 未同步补 token。
2. **写端点治理做得好**：51 个写端点注册表有运行时守门人用例，拒绝路径（鉴权 / RBAC / 参数校验 / 信封）全覆盖，是本项目的正面样板。
3. **读侧治理明显滞后**：43 个业务 GET 端点匿名、21 个 GET 端点零测试、RBAC 测试只守护 12 个 GET——与写侧的严谨形成反差，且存在"写要 researcher、读却匿名"的不对称。
4. **共享状态污染是系统性 Flaky 源**：会话级 `DATA_ROOT` 被多个模块级 fixture 写入，且 `test_api.py` 的 teardown 直接 `rmtree` 整个共享根（QA-09）、`test_lab_factor.py` 只清 DB 不清 parquet（QA-10）。当前靠字母序"碰巧"能跑通，属于**定时炸弹**。
5. **网络依赖隔离不彻底**：绝大多数网络用例已妥善 monkeypatch（正面），但 `test_universe.py:137` 与 `test_p1_data.py:80` 两条**真实触网**，且前者还会把真实行情写进共享测试仓（QA-11/12）。
