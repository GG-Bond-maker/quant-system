## 2. 源码修复

### 2.1 P0 —— `alerts.py`：预警静默失效

**问题**：`93fa52d` 给 `_load_latest_predictions` 加了 `filter_universe(..., require_universe=True)`，快照缺失时抛 `AQPException 51001`，被 `except AQPException: return set(), set(), None` 吞掉 → 调用方 `if not cur_k: return []`，预警规则静默跳过。

**修法：保留严格校验，只补留痕。**
没有采用"降级成 `require_universe=False`"的方案——那会产出**未经 ST/停牌校验**的 Top-K 榜单，等于拿未校验数据冒充已校验结果，违背数据真实性红线。

| 改动 | 说明 |
|---|---|
| 返回值加第 4 项 `degraded` | `cur_k, prev_k, snap_date, degraded` |
| 新增 `_TOPK_HEALTH` + `_mark_topk_health()` | 记录降级状态；**限频 warning**（盘中每 30s 评估一轮，原因不变时不刷日志） |
| 新增 `GET /alerts/health` | researcher 可见，暴露 `degraded` / `reason` / `snapshot_date` / `checked_at` |
| **prev 期失败改为放弃本轮** | **审查时新发现的衍生缺陷**（QA 未列） |

> **衍生缺陷**：原代码在 prev 期解析失败时构造一个空 DataFrame 当基准，会导致
> `sym in cur_k and sym not in prev_k` 对**所有** Top-K 标的成立 → **enter 风暴**（大量误报事件）。
> 现改为直接放弃本轮判定并留痕。

### 2.2 P0 —— `export.py:54`：导出阻塞事件循环

`export_backtest` 是 `async def`，却在函数体内**同步**调用 `_run(req)` 重跑整个 Top-K 回测，阻塞 asyncio 事件循环数十秒，**所有并发请求一起卡死**。

改为 `await asyncio.to_thread(_run, req)`。同文件 `:81` 的 `export_strategy_backtest` 本就写对了，`:54` 是漏改。

### 2.3 P1 —— `sync_service._run_repair`：同步目标日滞后一天

截止日由 `prev_trade_day(date.today())` 改为 `last_completed_trade_day(get_calendar())`，与 `_run_incremental` 统一「已收盘」语义。

原写法被 `domain/calendar.py` 的 docstring 明确列为反模式：盘后跑完 repair，数据仍落后 1 个交易日，用户以为修好了其实没修到最新。

## 4. Flaky 根因修复

### 4.1 `test_api.py`：不再清空共享数据根

原 teardown 执行 `shutil.rmtree(_TEST_DATA_ROOT)`，而 `_TEST_DATA_ROOT = get_settings().DATA_ROOT` 是 **conftest 为整个会话创建的共享临时目录**——一个模块的收尾会清空全会话数据仓库，导致后续模块行为取决于「是否排在 test_api 之后」。

改为只删本模块写入的路径：`daily_bar/symbol={SYM}`、`daily_bar_hfq/symbol={SYM}`、MODEL_DIR。

### 4.2 连带修 `test_lab_factor`（QA-10）

上面的修复**暴露**了一个被掩盖的问题：`test_api` 之前「顺手清空」等于帮 `test_lab_factor` 擦了屁股。该模块 fixture 写入 `features/version=test`、`predictions/date=202{5,6}1231`、`daily_bar` 年分区，teardown 却**只清 DB 的 CustomFactor，parquet 一个都没删**。

已补齐 parquet 清理。这直接修掉了全量回归中 3 条 `polars InvalidOperationError`（`test_monitor` ×2 + `test_write_endpoints_smoke::test_monitor_run_runs` ×1）中的 2 条。
