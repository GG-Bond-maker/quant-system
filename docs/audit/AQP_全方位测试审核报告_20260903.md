## 二、伪造数据检测 —— 发现 2 处 P0（已人工复核 + 数据库取证确认）

### 🔴 P0-1 autoSync 伪造 data_jobs「SUCCESS」记录，健康状态/日报/统计被污染

- **写点**：`backend/app/api/v1/datacenter.py:1076-1096` `_record_auto_sync()` 在同步**尚未执行前**向 `data_jobs` 插入 `status='SUCCESS', duration_ms=0` 的 `auto_incremental` 记录（仅作防重标记用）。
- **数据库取证**（`data/sqlite/aqp.db` 只读查询）：表内已存在 1 条该假记录 `('auto_incremental', '2026-09-02', 'SUCCESS', 0, ...)`；全库 grep 确认这是 data_jobs 的**唯一写入点**——同步真实结果从不落这张表。
- **污染链路（均已核实读取点）**：
  1. `/datacenter/overview` AKShare 健康（datacenter.py:236-246）：读最新一条 data_jobs 状态 → 即使同步失败或从未真正执行，也显示「green：AKShare 连接正常，最近同步成功」；
  2. AI 日报「近期流水线」节（report.py:61）：展示假 SUCCESS 条目；
  3. `/datacenter/task-stats`（datacenter.py:422-428）：`COUNT(*)` 不过滤，calls 计数包含 0 耗时假记录（latency AVG 有 `duration_ms > 0` 过滤，未污染）；
  4. `/ops` DAG 最近任务（ops.py:409）：同样展示假记录。
- **修复方向**：防重标记改存 kv（`data/.auto_sync.json` 本就持久化配置，追加 `last_run_date` 字段即可）或内存态；data_jobs 只由真实同步任务写入；同步结束后按真实结果落一条记录。

### 🔴 P0-2 StockDetail 头部把「模型级置信度占位」展示为「概率」，无口径披露

- **前端**：`frontend/src/pages/StockDetail/index.tsx:116-117` 标签写「概率」，渲染 `Math.round(predict.confidence*100)%`。
- **后端**：`backend/app/ml/predict.py:29-40` `_model_confidence()` = `clip(0.5 + 2×valid_rank_ic)`——是**模型级**常数（同一模型下所有个股同值），docstring 自认「占位」；metrics 缺失/NaN 时**静默回退 0.5**（用户看到恒 50%）。
- **问题**：它不是该股的上涨概率，与上次修复的「信心指数 ×1400+40」同型；响应无 `basis/kind` 披露，前端无 ⓘ。
- **修复方向**：① 后端 predict 响应加 `confidence_basis`（说明口径）+ metrics 缺失时返回 `null` 而非 0.5；② 前端标签改「模型置信度」并加 ⓘ（提示：模型级，非个股概率）。
