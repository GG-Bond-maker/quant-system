## 1. TL;DR

**一句话结论：功能"连得上"，但"没守好、没说完、没算准"三处有实洞。**

- **连得上** ✅：前后端端点 **109 ↔ 109 完全对齐，断链 0**。历史遗留的唯一断链 `/datacenter/sync/auto` 已确认修复；历史上踩过的 9 项坑中 6 项已修（回测导出同引擎、screener 用 `pool_size`、推理链路 propagate 等）。
- **没守好** 🔴：**42~43 个 GET 端点完全匿名**（占 109 端点的 39%），且**同资源读写不对称**——`POST /alerts/rules` 要 researcher 而 `GET /alerts/rules` 裸奔，`GET /datacenter/logs` 会把含堆栈和绝对路径的后端日志正文吐给匿名请求。`93fa52d` 这次"安全加固"只加固了写侧，读侧大面积漏网。
- **没说完** 🟡：后端已产出 `close_basis` / `feature_basis` / `label_price_basis` 完整口径披露，**前端一个都没消费**（`grep` 前端源码 0 命中）。现在是"哑弹"，但任何人把 `latest_close` 接上 UI，就会把后复权价（可能比现价大几倍）当最新成交价展示。另有 3 个后端能力前端无 UI（批量实时行情、编辑预警规则、同步任务详情）。
- **没算准** 🔴：**1 个 P0 功能性回归**——`93fa52d` 新增的 `require_universe=True` 闸门在股票池快照缺失时把异常吞掉，导致用户配置的"进入/跌出 Top-K"预警**既不触发、也不报错**（静默失效）。此外还有同步目标日滞后一天、回测换手率分母滞后一日、缺分标的被填 5% 权重等 6 处口径级偏差。

**全量回归未通过**：`8 failed / 629 passed / 5 skipped`（642 条，657s）。其中 7 条是测试侧欠账（老测试没跟上升权），**1 条是真源码回归（P0）**。

### 📌 主理人复核批注（齐活林）

两处对成员判定的**调整**，均记录理由以备追溯：

1. **A-01（`export.py:54` 同步调用）由 P1 升 P0**。架构师原判 P1，但影响面是「任意单个用户点一次导出 → 整个 asyncio 事件循环停摆数十秒 → **所有在线用户一起卡死**」，属于单点操作引发全局不可用，符合 P0 定义。

2. **C-01 / C-02 / C-03（管道零互斥）由「本迭代」上调至「立即修」**。此条采纳架构师收工前的主动补充：「若 A-01 因『影响全站』升 P0，C-01/C-02 建议一并评估——它们同属『用户一次操作破坏全局状态』性质」。

   **主理人复核后认同，理由有三**：
   - **后果不可逆**：A-01 卡死是暂时的，请求结束后自动恢复；而管道撞车会**静默覆盖** `daily_bar_qfq` / `cs/` 镜像分区，`atomic_write_parquet` 只保证单文件不半截，**不保证两个写者的先后顺序** → 产生的是**错误但看起来正常的数据**，可能长期不被发现地污染回测与选股。
   - **触发是必然而非偶然**：autoSync 固定 15:45、晚间 pipeline 固定 17:30，与用户手动 `POST /sync` / `/mirror/rebuild` 是**常态共存**的，碰撞窗口每天都在。
   - **修复成本相对低**：三把锁（`_sync.lock` / `_job.lock` / `compute_slot`）已经存在，缺的是一个统一的 `PIPELINE_LOCK` 把它们串起来，属"接线"而非"重写"。

   调整后**立即修由 4 项增至 5 项**。

## 6. 结论与建议路线

### 6.1 总体判断

**代码主干健康度中上**，历史踩过的坑大部分已沉淀为"带注释的纪律"并被遵守（这是本项目最值得肯定的部分：**失败路径不冒充真实值**这条红线执行得非常彻底）。

本次 `93fa52d` 的"生产安全加固"**方向正确但只做了一半**：写端点收紧到位（51 个全部纳管并有守门人测试），**读侧完全没动**，且读侧收紧后**老测试没同步补鉴权头** → 直接导致 7 条用例变红。同时新增的 `require_universe=True` 闸门引入 1 个 P0 静默失效。

### 6.2 建议修复顺序

1. **先止血（T-01 / T-02 / T-04 / T-05）**：P0 静默失效 + 事件循环阻塞 + 测试套件恢复全绿 + 管道互斥。这四项做完，`93fa52d` 才算真正可用。
2. **再补安全（T-03）**：读端点鉴权补齐，消除读写不对称。
3. **后补质量（T-05 ~ T-14）**：并发互斥、可观测性、性能预热、测试覆盖。
4. **技术债**：18 项排期项进看板。

### 6.3 两条流程性建议

- **安全加固类提交必须自带"读侧清单 + 老测试同步"检查项**。本次 8 条失败里有 7 条是"收紧了权限但没改测试"，这是可预测、可流程化避免的。
- **基线需要重设**：`mypy` 实测 **0 errors / 120 files**，与记载的 131 errors / 22 files 对不上。建议 CI 固定 `--ignore-missing-imports` 并把 0 errors 固化为门禁，防止劣化。

### 6.4 遗留风险（本次审查未覆盖）

- **未做真实 UI 层验证**：三位成员均为静态审查 + 后端测试，未启动服务跑真实浏览器流程（17 个页面全 `React.lazy`，Vite dev 需预热全路由才能判白屏）。
- **未做真实数据链路验证**：数据同步缺口（09-07 起 daily_bar 骤降）未复核是否已回补。
- **无 git remote**：代码零异地副本，且根目录存在 `.git.corrupt.bak-20260902`，说明**已发生过一次仓库损坏**（见架构师 O-02）。
