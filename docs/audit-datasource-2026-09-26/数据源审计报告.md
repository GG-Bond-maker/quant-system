# Alpha Quant Platform 数据源审计报告（多源降级容错前置审计）

- 审计日期：2026-09-26
- 审计范围：`backend/`（FastAPI，约 303 个 .py）数据获取链路；`frontend/` 仅用于提取数据契约基线（本次不改前端）
- 审计性质：**只读审计**。未修改任何业务代码、配置、数据、服务。
- 审计人：架构师 高见远（software-architect）
- 目标：为「多源降级容错（腾讯/新浪/BaoStock）+ 降低东财单点依赖」提供事实基线，不重写、不换架构、不引入 Tushare。
- AKShare 版本：`0.5.x`（site-packages 实测存在 `stock_a/`、`stock_feature/`、`stock_fundamental/` 等模块；判定依据均为包内被调函数的真实 URL/域名）

> 判定方法说明：所有「实际数据源」均由 `backend/.venv/Lib/site-packages/akshare/` 内**被调函数的源码 URL**核实（不是凭函数名推断），必要时由项目内直连 HTTP 的代码补证。凡无法确认者一律标注「未知 / 需进一步验证」，不做猜测。

## 0. TL;DR（现状与严重程度）

- 数据源分三层：① AKShare 适配器（`data/ingest/akshare_adapter.py`，已带限速+重试+按接口粒度的熔断）；② 交互式直连 HTTP（`data/realtime.py`、`data/etf.py`，多数已带降级链）；③ 本地 Parquet/SQLite 直接读取（**天然免疫东财故障**）。
- **东财依赖存在但被多处高估为"已降级"**：最关键的失实点是**项目把 `ak.stock_notice_report` 当作"新浪公告降级源"，但该函数底层其实是东方财富**（`np-anotice-stock.eastmoney.com`）。相关公告链路实际上**没有离开东财**。
- 真正「仅依赖东财、无备用」的功能集中在：**全市场实时快照（涨跌分布/异动）**、**主力资金流（大盘/个股/ETF）**、**北向资金/持股**、**股东信息（户数/十大流通股东）**、**个股财报关键指标（ROE/毛利率/净利率）**、**ETF 全市场资金净流入榜**、**ETF 行业配置**、**行业板块榜**、**乐咕乐股估值**。
- **与用户诉求冲突的硬发现**：`app/data/ingest/multi_source.py` 内存在 **Tushare 实现**（`_from_tushare`、`http://api.tushare.cn`、`get_settings().TUSHARE_TOKEN`），且 `config.py:222` 有 `TUSHARE_TOKEN` 配置项。该模块当前**仅被测试引用、未接入生产路径**，但**代码与配置层面违反"绝对禁止 Tushare"**，必须处理（见 §8.6）。
- 最小改动方向：**复用已有抽象**（`realtime._first_source` 降级链 + `akshare_adapter._safe_call`）而非新造；把东财主源补上腾讯/新浪/BaoStock 备用；公告改回真正的非东财源；删除 Tushare 残留。

## 5. 现有本地数据与缓存机制盘点

### 5.1 缓存层

| 层 | 位置 | Key 结构 / TTL | 是否区分交易日 |
|---|---|---|---|
| Redis（SWR） | `cache/redis_client.py` + `cache/swr.py`；key 工厂 `cache/keys.py` | `aqp:<ns>:...`；主键 TTL + `:swr` 影子键（`STALE_SUFFIX`） | 是——`k_market_overview(date, k)`、`k_market_overview_rt(date)`、`k_market_overview_daily(date,k)`、`k_stock_kline(symbol,adjust,start,end)`、`k_screener(date,strategy,top_k,board)`、`k_etf_detail(date,code,period)` 等 |
| 进程内 LRU（Redis 降级后备） | `cache/memory.py` | `LRUCache(maxsize=100k)`，`lru_set(ttl)` | 由调用方 key 决定（`aqp:pf:close...` TTL 600） |
| 进程内 dict（ETF） | `data/etf.py:49 _cache` | `cn_list`300 / `kline`3600 / `flow`300 | 否（按请求键） |
| 进程内 dict（行情快照） | `core/quotes_hub.py:64 _quotes_cache` | symbols 哈希，TTL=`QUOTES_TTL`(15s) | 否 |
| Parquet 落地 | `data/parquet_store.py`，`DATA_ROOT` | 见 §5.2 | 分区含 `date`/`year` |
| SQLite | `SQLITE_PATH` | 见 §5.3 | 表含 date |

SWR 降级策略（`cache/swr.py`）：`status=="unavailable"` **不落缓存**（快速自愈）；`status=="degraded"` 用 ≤15s 短 TTL 且不写影子键。（`DEGRADED_TTL_SECONDS=15`，`UNAVAILABLE_STATUS`/`DEFAULT_CACHEABLE`）

### 5.2 Parquet 数据集（`DATA_ROOT=data/parquet`，按 `symbol=<sym>/year=YYYY.snappy.parquet` 分区）

## 6. 前端数据契约清单（换源不得改动的前端基线）

### 6.1 个股 K 线（`GET /api/v1/stock/{symbol}/kline`）

- `north`：`date, hold_shares, hold_cap_yi, pct_of_float, source`（含 `retired:true` 永久下线态）
- `fundamentals`：`pe_ttm, pb, roe, gross_margin, net_margin, eps, bps, revenue_yi, net_profit_yi, report_date, note`
- `events`：`items[{title,date,url,source,event_type,sentiment}]`
- `holders`：`holder_num{...}, top10[], end_date`
- `chip`：`as_of,current_price,avg_cost,profit_ratio,trapped_ratio,p5,p95,concentration,lookback,curve[]`
- `risk`：`as_of,window,annual_vol,max_drawdown,sharpe,beta,vol_short,vol_percentile,benchmark,rf_annual,note`

### 6.3 市场概览（`GET /api/v1/market/overview` / `/overview/rt` / `/overview/daily`）

块：`indices, heat, money_flow, sectors, anomalies, recommend, ai_stats, sentiment`，每块 `BlockBase = { status, reason?, message?, as_of?, coverage?, freshness? }`。

## 8. 最小改动方案设计（架构建议，本阶段不落码）

### 8.1 先判断：项目已有类似的 Provider/Adapter 抽象 ✅（要复用，不要重造）

| 抽象 | 位置 | 说明 / 复用方式 |
|---|---|---|
| 单源安全调用（限速+重试+按接口熔断） | `data/ingest/akshare_adapter.py:237 _safe_call` / `_throttle` / `_SourceBreaker` | **已有的官方出口**。任何新的 AKShare 调用都应经它，禁止自建重试（`market_service` 头部注释已明确「不再自建重试包装绕过全局限速」） |
| 多源降级链 | `data/realtime.py:143 _first_source([...])` | 现成的「按序尝试、首个成功即返回、全败抛 `DataSourceUnavailable`」骨架；`fetch_quote`/`fetch_main_fund_flow`/`fetch_quotes_batch` 已在用 |
| HTTP 直连封装 | `data/realtime.py:104 _request`（限速+重试+编码） | `data/etf.py` 已 `from .realtime import _request` 复用；腾讯/新浪/BaoStock 直连应复用 |
| 标准化输出 | `akshare_adapter._standardize_daily` / `multi_source._standardize` | 统一 Polars schema（`date,open,high,low,close,volume,amount,symbol,code,source`） |
| 数据源标识 | `etf._LAST_CN_SOURCE` / `cn_etf_source()` | 口径披露范式：实际源随响应回传 |

**结论**：项目**已有** Fetcher/Adapter 抽象，无需新发明框架。扩源应**复用 `_safe_call` 与 `_first_source` 的命名与签名**，只增加新的源函数。

### 8.2 降级链设计

- **股票实时行情**：`腾讯（qt.gtimg.cn 批量，已有）→ 新浪（hq.sinajs.cn，已有）→ degraded`。`stock_zh_a_spot_em`（全市场）作为**全市场快照**的补充，失败走现有本地 `_heat_from_local`；不建议用 BaoStock 替代实时。
- **历史 K 线**：`东财 stock_zh_a_hist（主）→ 新浪 stock_zh_a_daily（备，已有）→ BaoStock（第三层，新增）`。仅在**前两源都失败**后才落 BaoStock。
- **指数**：`新浪（已有）/ 腾讯（已有）`，无需 BaoStock。
- **公告**：巨潮 cninfo（已有）→ 明确标注"仅东财"或引真正非东财源（**不得再把东财标成新浪**）。

### 8.3 统一输出适配层

新增源一律转换到项目**现有格式**（字段名以现结构为准）：`date/open/high/low/close/volume/amount/symbol/code/source`（见 `_standardize_daily`），不新增前端字段、不改前端结构。

### 8.4 异常降级规范

- 禁止裸 `except: pass`；每次失败至少记录（数据源名 / 接口名 / 请求参数 / 错误原因 / 失败时间）。现有 `_first_source` / `fetch_quotes_batch` 已按 `name:ExcType` 聚合 `errs`，可沿用并补全参数与时间戳。
- 全链路失败返回**项目原本定义的标准错误信封**（HTTP 恒 200 + 业务非零 code，`core/errors.py` 的 `ok/fail`），而非裸 500。现有 `etf_flow`、`market_service.build_money_flow`、`panels._cached_block` 已是此范式。
- 频率控制：每次请求**每源最多尝试一次**（`_first_source` 天然满足）；`_safe_call` 的 `AKSHARE_RETRY` 只对单源内部生效。

### 8.5 BaoStock 边界

- 只用于 **A 股历史行情兜底**：日/周/月 K、历史成交量额、涨跌幅、复权历史。**不替代**资金流向/龙虎榜/实时。
- **ETF 需单独评估**：BaoStock 覆盖以股票为主，ETF 覆盖有限，是否够用**未知/需验证**（见 §9）。
- BaoStock 需 `login()`/`logout()` 会话，且为独立 SDK（**会新增依赖**），与现有 `AKSHARE_RATE_LIMIT` 全局限速器**当前无集成**——需决定是否纳入同一限速域（见 §9）。

### 8.6 ⚠️ 与用户"绝对禁止 Tushare"冲突的必须处置项
