## 结论

审查发现的交易正确性、历史时点、来源追踪和六层连接问题已经完成代码修复，并通过离线端到端回归。资金、成交、费用、财务与公告可用时点、模型可用时点、回测到模拟交易来源均建立了可测试的约束。

图片中的六层能力已经形成可重复的离线闭环：

`数据与点时信息 → 财务/文本/价量因子 → 样本外预测与校准 → 含成本回测 → 绑定策略账户的模拟报单与成交 → 现金/持仓/费用/净值反馈 → 候选、理由、风险、报告和来源展示`

这不等同于生产环境已全部投入运行。生产 `alpha_multisource_v3g` 特征仍需重建，模型仍需训练、校准和显式 promote；真实外部行情、浏览器交互、退市数据覆盖与真实券商执行仍需运维验收。

## 优先级一：资金、成交、费用和历史时点

| 审查项 | 修复结果 | 关键验收 |
|---|---|---|
| S1 在途买单绕过资金和集中度 | SQLite 写锁内计算可用资金和在途敞口；下单冻结资金，撤单释放，撮合前再次校验现金与集中度；多账户隔离。 | 连续/并发多单不能双花；取消后冻结归零；历史成交不会被后来创建的委托冻结污染。 |
| S2 拒单被计为触发和收益 | 条件单与网格只有在报单成功、真实成交后才推进状态、成交计数和已实现收益；拒绝路径不产生虚拟利润，并通过订单来源字段关联真实母单/成交。 | Kill Switch 下拒单无成交、无收益；合法路径完成 `ACTIVE → SUBMITTED → FILLED`，网格收益来自成交账本。 |
| S3 条件单/网格 API 与网关主路径不可用 | 修复 API 会话、异常符号和网关报撤单协议；连接后的网关操作进入真实交易账本。 | 条件单、网格、网关报单、撤单释放、二次撤单失败和期货卖空拒绝均有行为测试。 |
| S4 重复扣冲击成本 | 冲击只进入实际成交价，现金只扣成交金额与显式税费；展示成本从成交价偏移还原，账户、净值、成交报告采用同一口径。 | 满足“初始资金 + 卖出回款 − 买入支出 − 显式费用 = 现金”；冲击不再二次扣减。 |
| S5 禁买池阻断卖出和紧急退出 | 禁买限制只阻止新开仓；已持仓仍可退出。Kill Switch 在同一写锁内撤销活跃单并释放冻结，紧急卖出仍可执行。 | 持有后进入禁买池可以卖出；熔断撤单覆盖账户，紧急清仓不伪造即时成交。 |
| S6 限价/对手价没有执行语义 | 请求模型、API、数据库、撮合和前端贯通价格模式、限价、目标股数；不满足限价不成交，到期取消并释放冻结。 | 限价买卖、过期释放、幂等重试改变执行语义时拒绝。 |
| S7 整手残额长期留在在途队列 | 拆单窗口、不足一手残额和缺行情订单具有明确终态；缺行情旧单不占用可执行扫描配额；三日 TWAP 重启先跳过已有成交再检查历史水位。 | 残额可终结，新单不被旧单饿死；跨三个执行日重启恰好成交 3000 股且最终 `FILLED`。 |
| S8 逐策略来源与执行反馈缺失 | 账户、母单、成交和 TCA 保存 `account_id/strategy_version/model_version/signal_id/backtest_id/run_id`；回测可生成模拟交易草稿；账户比较使用共同净值日和一致费用口径。 | TCA 不混账户；未知回测不能挂单；回测来源贯穿草稿、订单、成交、比较和日报。 |

交易账本另外处理了本地决策日、未来行情、非有限行情、同日买卖结算、缺估值、跨缺口净值、历史追插、目标股数、旧单扫描饥饿和网关空值契约。模拟账户不再用未来价格估值，也不会把缺数解释为空仓或零风险。

## 仍需生产运维验收

1. 在受控生产任务中重建 `alpha_multisource_v3g` 特征，核对财务/文本覆盖率、缺失原因和历史分区完整性。
2. 使用独立校准与样本外区间训练新模型，验收 Brier/ECE、区间覆盖和成本后表现，再显式 promote；本轮未修改生产模型。
3. 接入真实行情源执行断源、退市覆盖、交易日历和补跑验收；本机退市覆盖不足的问题不能由代码存在推断为已解决。
4. 做完整浏览器交互、任务重启、多账户并发和真实券商适配验收。当前成交仍是日线模拟，不提供盘口队列和日内成交量证明。
5. 旧数据库中 UTC/本地混写的 `created_at` 没有足够信息可靠区分，本轮没有批量改写旧订单；历史异常仍应通过独立账户按日期递增重放。
