# 交易正确性独立复核与完善（2026-10-28）

范围：仅修改 `backend/app/trading/paper.py`、`conditional.py`、`gateway.py` 及 brief 授权的五个交易测试文件。本轮没有修改 API、数据库模型、ML、前端、生产数据，没有提交 git。复核前已有 9 个闭环交易不变量测试通过。

## 发现与修复

1. **未来行情与缺估值**：`_bars` 默认及显式未来截止日期均不超过本地今天；网关市价金额因此也不读取未来收盘。账本查询只读截至估值日的成交。无行情、非有限价格或持仓标的在共同估值日断档时，保留持仓股数和成本，但 `last_price`、`market_value`、`pnl` 及账户权益返回 null 并告警，不把缺数据当现金空仓。净值按当日真实收盘价计算，不跨缺失日向前填充；有日历时把整日无行情的交易日也加入净值序列，含空缺时不计算跨断档 Sharpe/年化。
2. **本地决策日**：SQLite `func.now()` 为 UTC，本机午夜后刚创建的订单曾被写成昨日，能够错误地使用今日开盘成交。新订单显式保存当前本地决策时间，与撮合使用的本地日期一致。正常新单等待下一个执行日；紧急清盘同样不得伪造即时成功。
3. **目标股数与在途敞口**：卖单按明确的 `target_qty` 检查并冻结真实股数，不能用极小金额绕过持仓约束；买方金额必须覆盖目标股数的参考价。股数单按剩余股数执行，不因冲击后单价高于参考价而把一整手向下舍成零。补偿浮点整手边界误差；跳空及分批成交后按剩余股数乘真实成交价更新冻结金额和在途敞口，重启后继续执行且不重复成交。
4. **幂等完整性**：相同客户端标识重试核对算法、窗口、参与率、报价模式/限价、目标股数及模型/信号/策略/回测/run 等来源，拒绝改变执行语义或来源的请求。已有卖方金额单自动推导目标股数的重试仍保持兼容。
5. **历史账本**：撮合按账户已持久化最大成交日设置水位，禁止向更早日期追插成交从而改变已有后续卖出的持仓基础；该订单取消且写明原因。历史撮合不使用后来创建委托的资金冻结。A 股同日买入不可卖，ETF 的既有 T+0 规则保留。
6. **全局熔断与紧急退出**：开启 Kill Switch 在同一写锁中撤销所有账户已有活跃订单，释放冻结，返回撤单数。普通撮合在熔断时停止。紧急通道只允许卖方下单，`run_fills(force_sells=True, account_id=...)` 只处理所选账户卖单，保持全局熔断开启。跨模块 API 使用 setter 返回撤单数的请求已交主代理。
7. **真实执行窗口与队列**：有覆盖日历时按真实交易日确定窗口，目标执行日缺整根 bar 时不顺延至后来出现的价格，而是缺行情不成交、到期取消。无行情旧单不占用可执行订单数配额，避免 50 个缺数单永久阻塞后续有行情委托。没有覆盖日历时仍只能以已见 bar 序列定位窗口。
8. **费用与行情有效性**：成交价已含冲击，现金仅扣成交金额和显式税费；冲击成本的展示按实际股数乘价格偏移还原。非有限 open/volume/amount 拒绝参与撮合，不再生成 NaN 成交或抛出整数转换异常。资金守恒、真实卖出已实现收益、残额终态及账户隔离继续受回归覆盖。
9. **旧夹具纠正**：持仓/生产交易测试只提供过去行情，并把历史订单及决策价放到对应历史日。清盘测试验证新单尚待次日执行。条件单用可买入整手的真实隔离行情与资金；验证 `ACTIVE → SUBMITTED → FILLED`。网格验证真实买卖、在途不重复报单、成交计数和扣除双边成本后的实际收益，不再把触发或拒单当成交和利润。
10. **网关与同窗比较复核**：连接后的真实报单、冻结、撤单释放、二次撤单失败、期货卖空拒绝均有实际账本验证。不同初始资金和起始成交日的账户按共同净值日期计算收益；同窗基准缺真实价格时基准收益与超额收益为空。网关账户/持仓估值字段同步支持 null。

## Review 定向复修

- **三日 TWAP 跨日重启**：原水位检查发生在“该订单当日已成交”检查之前。第三次撮合枚举到第一日已存在成交时，错误当作新追插，甚至第二日重复撮合便会提前取消余单。现先跳过已有当日成交，再仅对真正的新成交执行历史水位保护。新增用例在三个执行日分别新建会话，逐日成交并重复调用撮合，核验 3 笔/3000 股、现金守恒、冻结完全释放及最终 FILLED；原真实历史追插拒绝用例仍通过。
- **绑定策略账户的条件单/网格**：原 `conditional:{id}` / `grid:{id}` 被当成 strategy_version，和账户 v1 冲突，合法触发报单遭拒。现优先使用账户绑定版本；无绑定版本时保留既有来源版本。条件单仍通过 client_order_id 与 fill_order_id 关联触发来源，网格通过 grid_bot_id 关联，未删除来源或放宽策略一致性校验。新增两个真实账户用例分别核验 SUBMITTED、继承 v1、来源关联、真实成交、网格成交计数及默认账户隔离。
- `trading-review-red.log`：新增三条业务回归 **3 failed**（TWAP 被 CANCELLED；条件/网格触发列表均为空）。`trading-review-green.log`：同三条及真实历史追插保护 **4 passed**。本轮只修改 paper.py、conditional.py、test_closed_loop_trading.py 与本报告，未扩大业务范围。

## 接口要点与剩余限制

- `account_summary(..., asof=date)` 可明确回放估值日；`run_fills(..., asof=date)` 截断至真实今天。账户 equity/market_value 可空；positions 的 qty、available_qty、cost_price 保持数值，last_price/market_value/pnl 可空，mark_date 可空。主代理和前端代理已收到契约。
- `set_kill_switch(...) -> int` 返回全账户撤单数；普通调用忽略返回值保持兼容。历史水位前追插采用显式取消，不重新计算或篡改已有成交。需要补历史账本时应在独立账户按日期递增重放。
- 既有数据库中旧订单 created_at 的 UTC/本地混用无法在无额外来源时可靠区分，本轮未批量改历史订单。生产历史越卖仍明确告警，不伪造修复后的成交。
- 行情与交易日历覆盖不全时不能恢复真实缺失行情；缺数订单不成交。未覆盖的日历区间使用已见 bar 定位窗口，仍需完整日历才能严格识别全部缺失交易日。无日历的当前估值按已完成工作日保守检查，节假日可能显示不可用，不能猜测完整权益。
- 当前是日线模拟：以已结束交易日的开盘和该日日成交额约束成交，不提供盘口队列或日内可得成交量模型，不等同真实券商可成交性证明。历史日线完成后才做离线撮合是本轮测试口径。
- 最终回归仍有 Starlette/httpx 既有弃用警告；没有跳过用例或放松真实资金、持仓、时点约束。
